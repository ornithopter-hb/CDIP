# 문서 작성 규칙

## 기본
- 모든 답변과 문서는 **한국어**로 작성한다.
- 문서는 `docs/` 아래 `.md`로 저장하고 `docs/00_docs.md`의 폴더 구조를 따른다. 새 폴더를 만들면 `00_docs.md` 표에 한 줄 추가한다.
- 날짜는 `YYYY-MM-DD`, 파일명에 공백 대신 `_`를 쓴다.

## 내용 원칙
- **팀 전체 논의 결과**를 기준으로 쓴다. 개인 아이디어 자료는 저장소에 올리지 않으며, 회의에서 다룬 범위만 회의록·주제선정 문서에 반영한다.
- **지어내지 않는다.** 회의록·제출물·강의자료에 있는 표현을 그대로 쓰고, 근거가 없는 수치·결정·평가는 쓰지 않는다. 비어 있는 칸은 `(팀 논의 필요)`로 남긴다.
- 확정되지 않은 사항은 **미확정**으로 명시한다 (예: "주제 미확정").
- 원본 자료(PDF·강의노트·녹음)는 저장소에 없다. 원본이 필요하면 작업자에게 파일을 요청하고, 추측으로 채우지 않는다.

## 출처 표기
- 원본 기반 문서는 제목 아래에 출처 인용 블록을 둔다. 경로는 과목 폴더 기준 상대경로로 쓴다.
  ```
  > 출처: `회의록/융합설계 및 지식재산권_daily report_ 0928_ 3반 1조.pdf`
  ```
- 원본이 여러 개이고 내용이 다르면 어떻게 합쳤는지 한 줄로 밝힌다.
- 웹 자료는 제목과 URL을 함께 적는다.

## 보고서 작성 원칙 (강의노트 `3주차_2_Report.pdf`)
- 좋은 보고서의 7가지 법칙: 간결하다, 단순하다, 명쾌하다, 체계적이다, 정확하다, 묘사적이다, 평소 쓰는 말을 사용한다.
- 서론(배경·주제·목적) → 본론 → 결론. 결론은 꼭 넣고, 중간 보고일 경우 향후 계획과 함께 쓴다.
- '상당히', '다소', '매우', '약간' 같은 명쾌하지 않은 단어 대신 수치로 쓴다.
- 그림과 표에는 순차적인 번호를 부여하고, 본문에서 꼭 언급(설명)한다.
- 목차는 대/중/소 번호를 부여한다. 회의록 등은 부록으로 돌린다.

## 갱신 순서
회의나 결정이 생기면 `docs/` 문서 → `README.md`의 진행 현황 → `CLAUDE.md`의 "현재 단계" 순으로 갱신한다.
