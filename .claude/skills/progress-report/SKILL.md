# Progress Report 초안 작성

대상: **PR$ARGUMENTS** (번호가 없으면 먼저 몇 번인지 묻는다)

## 1. 요구 항목 확인
- `.claude/rules/course.md`의 "Progress Report 항목"에서 해당 PR의 항목을 그대로 가져온다. 항목 번호와 문구를 바꾸지 않는다.
- 같은 파일의 수업 일정에서 해당 PR이 표시된 수업날을 찾고, 마감(그날 + 7일, 24시)을 계산해 적는다.
- PR7처럼 항목이 없는 경우 작성하지 말고 사용자에게 수업 공지 내용을 요청한다.

## 2. 자료 수집
- 저장소 안: `docs/01_회의록/`, `docs/02_주제선정/`, 이전 `docs/03_ProgressReport/`.
- 저장소에 없는 자료(강의노트, 조사 자료, 손그림, 도면 등)가 필요하면 사용자에게 요청한다.
- 외부 조사가 필요한 항목(예: PR1 다른 단체의 윤리헌장, PR3 특허 조사)은 웹 검색으로 찾고 제목·URL을 남긴다. 찾지 못한 것은 찾지 못했다고 쓴다.

## 3. 작성
- 파일: `docs/03_ProgressReport/PR<번호>.md` (폴더가 없으면 만들고 `docs/00_docs.md` 표에 추가)
- 구조:
  ```markdown
  # Progress Report <번호> — 3반 1조

  - **해당 Step**: 
  - **제출 마감**: YYYY-MM-DD 24:00 (아주 BB)
  - **작성 상태**: 초안 / 팀 검토 완료

  > 출처: 

  ## 1. <요구 항목 1 문구 그대로>
  ## 2. <요구 항목 2 문구 그대로>
  ...
  ```
- `.claude/rules/docs.md`의 내용 원칙·보고서 작성 원칙을 따른다. 팀이 정하지 않은 내용(윤리헌장 문구, 선정 결과, 점수 등)은 지어내지 말고 `(팀 논의 필요)`로 남기고, 채울 수 있는 초안 후보가 있으면 "초안 후보"로 구분해 제시한다.

## 4. 마무리
- 작성 후 사용자에게 비어 있는 항목과 팀 논의가 필요한 항목을 목록으로 알려준다.
- 커밋은 요청이 있을 때만 `[보고서] PR<번호> 초안 작성` 형식으로 한다.
